# OneFS Log Intelligence - Complete Project Guide

## 🎯 Project Overview

A full-stack application for **Dell EMC Isilon OneFS** log intelligence analysis, featuring real-time incident detection, pattern matching, and comprehensive analytics dashboard.

### Current Status
- ✅ **Backend API**: Fully functional FastAPI service
- ✅ **Database**: PostgreSQL with Alembic migrations
- ✅ **Job Processing**: Celery workers with Redis queue
- ✅ **Frontend**: React app with authentication and routing
- 🔄 **UI Integration**: Pages need API integration completion

## 🗄️ Database Schema

### Core Tables

#### Jobs Table
- **Purpose**: Track log processing jobs
- **Key Fields**: id, filename, status, progress, timestamps
- **Indexes**: status, created_at

#### Incidents Table
- **Purpose**: Store detected incidents
- **Key Fields**: id, title, severity, status, raw_log
- **Foreign Keys**: node_id, pattern_id, job_id
- **Indexes**: severity, status, created_at

#### Nodes Table
- **Purpose**: OneFS cluster node information
- **Key Fields**: hostname, ip_address, node_type, version
- **Indexes**: hostname

#### Patterns Table
- **Purpose**: Incident detection patterns
- **Key Fields**: name, regex_pattern, severity_level, category
- **Indexes**: is_active, category

## 🔍 OneFS Integration

### Supported Patterns
The system detects 23+ OneFS-specific patterns:

#### Hardware Issues
- Disk failures and SMART errors
- Memory errors and ECC issues
- Network interface problems
- Power supply failures

#### Service Issues
- Isilon service failures
- Process crashes and restarts
- Configuration errors
- License issues

#### Performance Issues
- High CPU usage
- Memory pressure
- Disk space warnings
- Network bottlenecks

#### Security Events
- Authentication failures
- Permission denied errors
- SSH access attempts
- Audit log events

#### Cluster Events
- Quorum changes
- Node failures
- Network partitions
- Upgrade events

### SSH Tunnel Setup
```bash
# Create SSH tunnel for OneFS access
ssh -N -L 0.0.0.0:8080:${ISILON_HOST}:${ISILON_PORT} \
  -p ${ISILON_SSH_PORT} \
  -i /path/to/ssh/key \
  -o StrictHostKeyChecking=accept-new \
  ${ISILON_USER:-root}@${ISILON_HOST}
```
> Never use `StrictHostKeyChecking=no` — it makes the tunnel trivially
> MITM-able. `accept-new` pins the host key on first connection; pre-seed
> `known_hosts` (or set ONEFS_HOST_KEY) for fully strict checking.

## 🐛 Troubleshooting

### Common Issues

#### Frontend Not Loading
```bash
# Check nginx proxy
docker-compose logs nginx

# Check frontend build
docker-compose exec frontend npm run build

# Verify API connectivity
curl http://localhost:8000/health
```

#### Jobs Not Processing
```bash
# Check Celery workers
docker-compose exec worker celery -A inspect active

# Check Redis queue
docker-compose exec redis redis-cli llen celery

# Check worker logs
docker-compose logs worker
```

#### Database Issues
```bash
# Check database connection
docker-compose exec postgres psql -U postgres -d log_intelligence

# Run migrations
docker-compose exec api alembic upgrade head

# Check database logs
docker-compose logs postgres
```

#### Authentication Problems
```bash
# Clear browser cache
localStorage.clear()

# Check JWT tokens
curl -H "Authorization: Bearer $TOKEN" http://localhost:8000/api/v1/jobs

# Verify user credentials
docker-compose exec api python -c "from src.core.auth import verify_user; print(verify_user('admin', 'admin123'))"
```
